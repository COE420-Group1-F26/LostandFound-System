# Software Process Model

## 1. Selected Software Process Model

Our team selected the Incremental Model for the development of the Lost and Found Property Claim System. In this model, the system is developed and delivered in smaller functional increments rather than building the entire system at once. Each increment adds new functionality until the complete system is developed.


## 2. Justification

The Incremental Model is suitable for our Lost and Found Property Claim System because the project consists of several features that can be developed gradually. Instead of implementing the whole system at once, we can divide it into smaller increments.

For example, the first increment can focus on the basic reporting features, allowing students and staff to report lost and found items. A later increment can introduce searching and matching between lost and found reports. After that, we can add notifications and claim verification, followed by the admin dashboard used by campus security or administrative staff.

This approach allows us to have a basic working version of the system early in the project. It also gives our team the opportunity to test each part before adding more features. Since project requirements may change or become clearer during the semester, the Incremental Model also gives us flexibility to make improvements in later increments without having to rebuild the entire system.


## 3. Overheads Associated with the Model

One overhead of the Incremental Model is the additional planning and coordination required to divide the project into appropriate increments. The team must decide which features should be developed first and make sure that each increment works correctly with the previous ones.

There is also repeated testing and integration work because every new increment must be tested individually and then tested again with the existing system. For example, when the matching feature is added, we must make sure that it works correctly with the existing lost and found item reports. This can require additional development and testing time.


## 4. Strategy for Managing the Overheads

To manage these overheads, our team will divide the project into clear increments and establish the order in which the main features will be developed. The basic and essential functions, such as reporting lost and found items, will be developed before more advanced features such as matching, notifications, and claim verification.

Tasks will also be divided clearly among team members to reduce confusion and duplicated work. We will use GitHub to manage our project files and keep track of changes made by each member. Each increment will be reviewed and tested before the team begins working on the next major increment.


## 5. Drawbacks of the Model

A possible drawback of the Incremental Model is that integrating a new increment with the existing system may cause problems. For example, adding claim verification or notifications may require changes to previously developed reporting or matching features.

Another drawback is that the overall architecture of the system needs to be planned carefully from the beginning. If the database or system structure is poorly designed in an early increment, adding later features such as the admin dashboard or matching functionality may become more difficult.

There is also a possibility that the team may focus too much on completing individual increments without considering how all parts of the final system will work together.


## 6. Strategy for Addressing the Drawbacks

To reduce these drawbacks, our team will define the main system architecture and database structure before developing the major features. This will help ensure that future increments can be added without requiring major changes to previously completed work.

Each new increment will also be tested with the existing system before it is considered complete. If a new feature affects an earlier feature, the team will review and test both parts together. GitHub will be used to track changes and maintain previous versions of the project in case a problem needs to be identified or corrected.

The team will also regularly review the overall project requirements to make sure that the individual increments continue to support the main objective of providing a centralized and secure system for reporting, finding, and claiming lost property on campus.
