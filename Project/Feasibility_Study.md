# Initial Feasibility Study

## 1. Technical Feasibility

The Lost and Found Property Claim System is technically feasible because it can be developed using technologies and tools that are available to our team. The system will be developed as a web application, so it does not require specialized hardware or the development of a separate mobile application.

The main technical requirements include a user interface, a database for storing lost and found item reports, search and matching functionality, notifications, claim verification, and an admin dashboard. These features can be implemented using common web development and database technologies.

The team also has experience with programming, databases, Git, and GitHub. GitHub will allow us to manage different versions of the project and collaborate throughout development. Some features, particularly automatic matching and notifications, may require additional learning and testing, but they are achievable within the technical scope of the project.


## 2. Economic Feasibility

The project is economically feasible because the expected development costs are low. The system is being developed as a university course project by the team, so there are no employee or professional development costs.

Most of the software development tools required for the project are free or available to students. GitHub can be used for version control and collaboration, and common programming and database tools can be used without requiring expensive software licenses.

The project also does not require specialized hardware. The team can use their existing computers for development and testing. Therefore, the main resources required are the team's time, available computers, internet access, and software development tools.


## 3. Operational Feasibility

The system is operationally feasible because it addresses a real problem experienced by students and staff on campus. Currently, lost items may be reported through informal methods such as group chats or word-of-mouth, which can make the process disorganized and make it difficult for owners to recover their belongings.

The proposed system provides one centralized platform where students and staff can report lost or found items, search existing reports, and receive notifications about possible matches. Campus security or administrative staff can use the admin dashboard to manage reports and verify claims before items are released.

The intended users are likely to benefit from the system because it provides a more organized and convenient process for reporting and recovering lost property. Claim verification also helps reduce the risk of an item being given to the wrong person.


## 4. Schedule Feasibility

The project is feasible within the available course duration because the system can be divided into smaller increments. The team can first develop the basic reporting functionality and then gradually implement searching, matching, notifications, claim verification, and the admin dashboard.

The scope has also been limited to make the project manageable. Features such as a mobile application, UAE Pass integration, external police or city database integration, payment or reward systems, and real-time chat are not included in the current version.

By dividing tasks among team members, following a clear development schedule, and testing features as they are completed, the team should be able to complete the major project features and deliverables within the course duration.


## 5. Overall Feasibility

Based on the technical, economic, operational, and schedule analysis, the Lost and Found Property Claim System is feasible as a course project. The required technologies and development tools are accessible to the team, the expected financial cost is low, and the system addresses a genuine need for a more organized lost and found process on campus.

The main constraints are the limited course duration, coordination between team members, and the technical effort required for features such as matching, notifications, and claim verification. However, these constraints can be managed by using the Incremental Model, dividing the work into manageable parts, maintaining a clear project scope, and regularly testing and integrating completed features.
